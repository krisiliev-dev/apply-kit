Design notes
  • The first thing the panel says is what it recognised and why it's sure (job ID matches the package's target posting). If that line is wrong, Kris stops before anything else happens.
  • Fields are grouped by the portal's own pages, in the portal's order, so the list and the page line up. Each row says where its value came from (profile, answer bank, CV version), in text, not only colour.
  • "Ready" vs "filled" is honest about Workday's one-page-at-a-time model: 18 answers are ready, but only the current page can be filled.
  • On the portal, filled fields get a thin green edge and needs-you fields an amber one, so the panel and page cross-reference at a glance. Pause and "Undo this page" are always there.
Design notes
  • apply-kit never generates, sees or stores passwords: it puts the cursor in the field so the browser's own password manager offers a strong one and saves it per portal.
  • Email defaults to the job address because it closes the loop: the verification and later confirmation/rejection emails reach the job mailbox and update tracking.
  • Terms checkboxes are never ticked for Kris. The verification link is surfaced from the mailbox but opened by him.
Design notes
  • A page stepper mirrors the portal's. Finished pages collapse to one line; the current page is open.
  • Workday's own CV parsing often adds duplicate jobs with wrong dates. apply-kit undoes that and says so, with the removed entries one click away (nothing disappears silently).
  • The panel waits for Kris to press the portal's Next/Save and continues when the next page loads; it never clicks navigation itself.
Design notes
  • Only fields it can't answer confidently reach Kris, each as a ready-to-accept draft with its basis shown. Exact answer-bank hits fill silently; fuzzy hits below the bar are named and refused, not guessed.
  • Drafts stay inside the honesty line: the screening answer cites the profile entry it came from. The character count is shown against the portal's limit.
  • "Save to answer bank" is on by default, so the same question is never typed twice (the zero-retyping measure). Input types match the question: number, textarea, radio.
Design notes
  • When a portal rejects a value, the panel says which field, what happened and what to do. It offers the value ready to copy (formatted the way the field wants), so recovery takes seconds.
  • It retries once on request, never in a loop that could fight the portal. "Report" keeps the details locally for fixing the filler.
Design notes
  • The reminder is the focal element: a heavy-bordered box saying Kris presses Submit. On the portal, the Submit button is highlighted but never pressed.
  • A short summary of anything unusual (manual paste, blanks by rule, new answers saved) tells Kris what to look at on the review page.
Design notes
  • The confirmation page is only a hint. Kris confirms, because the Application should only exist if he really submitted.
  • "Mark as submitted" creates the Application with the package linked and a follow-up date. If he forgets, the confirmation email prompts the same question later, so nothing is lost.
Design notes
  • No package means no tailored CV, so the panel doesn't fill a generic one by default. It steers to capture → prepare → come back, keeping "quality held".
  • "Fill name and email only" is a quiet escape hatch for trivial forms (open question: keep it or drop it).
Design notes
  • When it doesn't know the portal, it fills nothing rather than guessing into a bank's own Bulgarian form. The fallback is a copy list in the form's order, one click per value, with "Copied" feedback.
  • The package's Bulgarian CV and letter are offered because the form is in Bulgarian. Best-effort label matching is opt-in and marks what it touched.
Design notes
  • Click-only capture: nothing is read until Kris opens the panel on a page, keeping LinkedIn use user-driven.
  • Extracted fields are editable before adding, with a quick fit check so he can decide here whether it's worth it. Empty values say "not stated" rather than staying blank.
  • It checks for duplicates and spots the company's real ATS, offering to watch it so future jobs arrive without capture.
Design notes
  • The extension holds no personal data of its own, so when the app is down it says so plainly, retries in the background and keeps Kris's place.
