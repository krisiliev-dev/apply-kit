Your master profile is empty

Every CV, cover letter and portal answer is built from it. Setup imports your old CVs, lets a coach question them, then sets up your search. About 30–45 minutes; you can stop any time.

Start setup

The quick start works, but your first packages will be thinner. The profile fills in from questions asked while you apply.

Design notes
  • Pieces are grouped by role because that's how a CV reads and how you remember your work. Skills not tied to a role get their own group.
  • Each piece shows four things at a glance: tags (for matching requirements), angle, status and source. The source keeps the profile auditable: every line traces back to a file, the interview or a package.
  • The section tabs carry a count only when something needs you (see "Unconfirmed"), so the badge means something.
  • No loading state: the profile is a local file and opens instantly. Long groups show the first few pieces with "Show more".
Design notes
  • Phase C of onboarding. Answers given to gap questions inside a package become unconfirmed pieces. They're used for that job only until you confirm them here.
  • Each card quotes the question and your original answer, so you can check that the rewrite didn't stretch it.
  • Near-the-line pieces get their own decision with a suggested honest version, and are never bulk-confirmed.
  • Discarding never changes a package already sent; it says so, so the action doesn't feel risky.
Design notes
  • Single column, top-aligned labels, help text under each label. Fields are validated on blur; when you press Save, a summary at the top links to each field.
  • The honesty-line check compares the edit against the original source (shown on the right) and offers one-click honest fixes instead of only saying no.
  • "Where does the number come from?" decides how firmly tailoring states it. It's required only when the text contains a number.
  • Delete is a quiet link with a confirm step. Editing never changes packages already sent.
Design notes
  • Three cards side by side so the angles can be compared; they stack at narrow widths. Each card has an editable summary line and an ordered "leads with" list.
  • A thin angle is flagged with the reason ("6 pieces, 1 with a result") and a fix: a short coach session about design work.
Design notes
  • The table shows which answers are used and which are stale ("Last used", "Used"), so the bank stays trustworthy for the extension.
  • When an answer was changed in a portal, the extension notices and asks which version to keep. The bank learns without silently overwriting.
  • Long answers truncate to two lines; the full text shows on hover and in Edit. Questions that need a fresh answer per job aren't stored.
Design notes
  • Voice is shown as readable rules with evidence, not a black box. Each rule can be removed if it's wrong.
  • "Local only" is stated at the top because these are the most personal files in the app.
  • Edits to drafts feed the voice automatically and can be paused. An unreadable sample says why and how to fix it; the rest still count.
Design notes
  • Each dealbreaker shows how many jobs it hides today and links to the hidden pile, so a rule that's too strict is easy to spot.
  • Rules changed from the Feed ("Not a dealbreaker for me") show up here with where and when, so the rules never drift without a record.
