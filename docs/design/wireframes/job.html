    Design notes
    • Header answers "what and is it worth it" in one line; the three actions sit right of it so the decision is reachable without scrolling. Prepare package is the only primary.
    • Order of the main column follows the decision: fit check (verdict) → requirements (evidence) → dealbreakers (deal-killers) → key facts → raw text. The full posting is collapsed: the extraction should save the read, and "Show where" proves it didn't invent anything.
    • Requirements table names the evidence for each "met", so the same evidence carries into the CV step's requirement → evidence map. "Not held" (CISSP preferred) is amber, a required gap red: preferred items never count as gaps.
    • Postings: the target posting (thick left rule) defaults to the company's own page because it goes straight into their ATS and the extension can fill it. Split is always offered because merging is a guess.
    • J/K keep working here, so you can walk the Feed in order from inside the detail view.
    • At 400px: the side column drops below, header actions wrap under the title, facts stack label over value, table scrolls inside its box.
    Design notes
    • Warning, not a block: re-applying to a company for a different role is normal. The banner gives date, role and outcome so you don't have to dig.
    • The rejection reason is quoted from the matched email (job 3 feeds back into job 1), plus what changed since, so the new package can address it.
    • Applying to the same job twice would be a stronger warning that asks for confirmation before Prepare package.
    Design notes
    • Extraction accuracy is riskiest assumption #2, so low confidence is shown, never guessed silently: the source line is quoted with the unclear part marked.
    • Radios, with the most likely reading pre-selected and the reason next to it. "Don't know" is a valid answer.
    • Until answered, the fit check uses the cautious reading (salary "not stated", the higher year count) and says so: a job is never promoted on a guess.
    • Prepare package isn't blocked: these answers affect ranking and the salary answer, not the CV. The salary question comes back in the Screening answers step if still open.
    Design notes
    • Answers PRODUCT.md's open question in favour of "extract directly, show in English": requirements are read from the original; quotes keep the Bulgarian text with a translation, so you can check the reading.
    • "View original" opens the untouched text (marked lang="bg" for screen readers).
    • The posting allows either language, so the package defaults to English (PRODUCT.md) with a one-click switch.
    Design notes
    • Nothing disappears silently: a closed job stays reachable, says when and how it closed (which source, which check), and keeps the last saved copy.
    • Prepare package is disabled with the reason written next to it, not just greyed. "Reopen" covers the case where our check is wrong (the source-drop guard from the Feed).
    • Empty-ish state with a next step: similar open jobs ranked the same way, plus a watchlist boost.
    Design notes
    • What's known from the Feed row (title, company, location, sources) shows at once; only the extracted parts are skeletons shaped like the real table.
    • 5–10 s, so a step list with what's done and what's next, not a spinner. Results replace skeletons per section as they arrive.
    • Save and Pass don't need extraction and work immediately; Prepare says why it's waiting.
    Design notes
    • Says what failed, why, and that nothing was lost; the retry is in the banner. Saving queues an automatic retry, so you don't have to remember.
    • Raw posting text stays readable: the failure blocks the package, not the decision.
    Design notes
    • One required choice with a pre-selected reason guessed from the fit check (the gap); the note is optional and marked so.
    • The "rank lower" checkbox is opt-in and specific: it adjusts ranking, it doesn't create a dealbreaker that hides jobs.
    • Pass is undoable for the session and the next job opens, keeping the Feed's keyboard rhythm.
