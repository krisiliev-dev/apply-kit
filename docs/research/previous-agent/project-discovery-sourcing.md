Discovery sources for the user's goal (cybersecurity, Sofia / Manchester / remote-EU), as built 2026-05:

- **dev.bg** is the prime Bulgarian source. Its `/company/jobs/it-security/` category is server-rendered and **robots.txt permits it**, so it has a dedicated adapter `lib/discovery/sources/devbg.ts` (cheerio on `.job-list-item` → `.job-title`/`.company-name`/`.badge`). Yields ~20 real Sofia security roles (A1 Bulgaria, DSK Bank, Yettel, Nexo, EGT…).
- **jobs.bg is OFF-LIMITS** — its robots.txt itself sits behind a Cloudflare bot challenge; crawling would require defeating bot detection. Not built. Route to extension-capture instead.
- **HN "Who's hiring"** resolves the monthly thread via the **HN Algolia API** (`hn.algolia.com/api/v1/search_by_date?tags=story,author_whoishiring`), not HTML scraping (the old scrape silently returned 0).
- **WeWorkRemotely RSS** (`/remote-jobs.rss`, `/categories/remote-devops-sysadmin-jobs.rss`) for remote roles.

**Boundary held (twice, including a claimed-permission push):** do NOT build automation that drives an authenticated **LinkedIn** session — the technique (defeating anti-bot on a logged-in session) is declined regardless of stated permission; the legit route is LinkedIn's official API or the user's own-session browser-extension capture. Same principle blocks jobs.bg's Cloudflare gate. See [[feedback-no-personal-data]].

**Browser extension** (built at `extension/`, no-build MV3, load-unpacked): captures postings from the user's own logged-in LinkedIn/jobs.bg/Indeed/Glassdoor sessions (JSON-LD-first DOM extraction) → POSTs to `/api/discover/ingest` → server pool. This is the sanctioned route for LinkedIn/jobs.bg. Source kinds `jobsbg` + generic `capture` added for it; jobs.bg extractor is detail-page-only (`.job-view-title` + og:title parse — list pages are anchor-less MDC SPA). Live DOM extraction is best-effort.

**ATS adapters built** (`lib/discovery/sources/`): `smartrecruiters.ts` (public API; ref `companyId` or `companyId:country`, e.g. `BoschGroup:bg` → 14 Sofia roles) and `workday.ts` (CXS API; ref = careers URL, e.g. A1 `https://a1group.wd3.myworkdayjobs.com/bg-BG/A1_Jobs`). Both dispatched in `/api/discover/run`'s direct-crawl loop. `source.company` is the stable expiry key (companyId / tenant); `posting.company` is the display name. NOTE: editing `mcp/server.mjs` (e.g. the `add_source` kind enum) needs a Claude Code restart to take effect in-session; register new-kind sources via HTTP `POST /api/discover/sources` meanwhile. Registry sources are agent-managed (no browser UI to add them).

**Email-alert ingestion built** (Gmail IMAP): `lib/discovery/email/{imap,parse}.ts` (imapflow + mailparser + @types/mailparser deps), `POST /api/discover/email-sync`, MCP `sync_email`. Reads LinkedIn/jobs.bg saved-search alert emails from the user's inbox (env `GMAIL_USER`/`GMAIL_APP_PASSWORD`/`GMAIL_MAILBOX`), parses per-sender (best-effort — needs real-sample tuning), ingests to pool. Setup: docs/email-alerts.md.

**Scheduler + full-detail capture built**: Settings `discovery.autoRefreshEnabled/IntervalMinutes` (lib/settings) + `components/sync/DiscoveryAutoRefresh.tsx` (in-app loop, min 30min) POSTs `/api/discover/run` + `/api/discover/email-sync` on cadence; always-on via cron (docs/email-alerts.md). Extension now captures FULL detail of the page you open: salary from JSON-LD MonetaryAmount; jobs.bg description read from the same-origin `#customJobIframe` contentDocument. **Paid LinkedIn-data vendors rejected**: Proxycurl (sued by LinkedIn, shut down 2025 — used fake logged-in accounts); Bright Data/Coresignal (public-data scraping, court-defended but PAID → no-budget constraint rules them out).

**Aggregator adapters built**: `lib/discovery/sources/jooble.ts` (`JOOBLE_API_KEY` now SET in .env.local; ref `keywords|location`; covers Bulgaria + 68 countries — **best free BG-local cyber feed**: ref `cyber security|Bulgaria` → ~11 real Sofia roles at Crypto.com / Nexo. NB use location `Bulgaria` not `Sofia` — `Sofia` returns 0; no location floods with US roles) and `arbeitnow.ts` (free, no-auth; EU/remote; ref = keyword filter). **Adzuna excluded** (no Bulgaria in its country list). **No aggregator carries LinkedIn** (LinkedIn is direct-post-only).

**Free job-API adapters built** (`lib/discovery/sources/jobapis.ts`, 2026-05) — all six share ONE source kind `jobapi` with a `provider` tag (keeps the type/UI ripple to one kind; `SourceBadge` shows the provider). Ref format `keywords` or `keywords|location`. Registered via HTTP `POST /api/discover/sources` (kinds: reed/remotive/jobicy/themuse/findwork/eures):
- **Reed** (`REED_API_KEY` in .env.local — free at reed.co.uk/developers): UK incl. **Manchester**; Basic auth `KEY:`. Yields ~162 real Manchester cyber roles WITH salaries. The one good Manchester source (no aggregator covers UK cities for free).
- **Remotive** / **Jobicy** / **The Muse**: no key; remote/global. Jobicy & The Muse filter a recent feed by keyword client-side so they return few matches (1–17) — low yield, kept anyway.
- **Findwork** (`FINDWORK_API_KEY` set in .env.local; Token auth). Registered ref `security engineer`. It's a SMALL GENERAL tech board with loose keyword search → returns ~88 mostly broad remote-tech roles (SWE/CS/Ops), NOT precise cyber. Useful as broad remote-tech coverage; /discover scoring sinks the non-cyber ones.
- **EURES** (EU/EEA public portal, no key/auth): the portal's own search endpoint `POST https://europa.eu/eures/api/jv-searchengine/public/jv-search/search`. **Covers EU/EEA + CH, NOT the UK (post-Brexit)** — so it's a remote/EU-wide cyber feed, NOT a Manchester or (effectively) Sofia one. Free-text keyword search is noisy (BG postings are local-language → "security" matches "сигурност/секюрити" = physical guards). So for cyber refs (alias set: cyber/cybersecurity/cyber security/ict security/information security/infosec) the fetcher switches to **ESCO occupation-URI filtering** (`occupationUris`, language-independent) using 6 baked-in ICT-security ESCO occupation URIs → clean ~50/run of OT Security Architect / Information Security Officer / Senior Security Engineer across AT/MT/etc. ESCO URIs resolved via `https://ec.europa.eu/esco/api/search?text=...&type=occupation`. **BG-specific EURES + occupation filter = 0** (BG public listings aren't ESCO-tagged for ICT security). Registered source: `eures` ref `cyber security` (EU-wide, no location).

**Orphaned-postings gotcha:** deleting a discovery source does NOT remove its postings — `/api/discover/run` expiry only closes postings under keys *crawled that run*, so a deleted source's postings linger in the pool forever. No purge endpoint exists. Cleaned 100 noisy EURES keyword-mode orphans by editing `~/.cv-maker/data/discovery-postings.json` directly (filter out, backup `.bak` left). Pool ~507 open after, incl. 50 clean EURES.

**ToS conclusion (researched 2026-05):** there is NO ToS-compliant way to *automatically pull directly* from LinkedIn/jobs.bg servers — LinkedIn UA bans all bot/automated access (even own-session; hiQ confirmed contractual breach even for public data), jobs.bg is Cloudflare-bot-gated. The compliant "automatic" pattern is **inverted**: platforms PUSH (email job alerts) → automate ingestion (built: email-sync); plus aggregator APIs (licensed redistributors) + user-driven extension capture (must stay user-driven, not auto-crawl). Make it hands-off via a scheduler (cron / in-app loop hitting `/api/discover/run` + `/api/discover/email-sync`) — not yet built.

**Location filter fix (important):** scoring `regionAliases` had no Bulgaria, and `EU` excluded it — so with `workAuth:["UK","EU"]` every Sofia role ("София"/"Sofia, bg") was being **hard-rejected** (invisible). Fixed in `lib/discovery/scoring.ts` + new `lib/discovery/location.ts` (Cyrillic→Latin normalize): Bulgaria added to EU + a BG code, `preferredLocations` now applies a soft boost (was unused), Serbia/Belgrade correctly rejected.

**How to apply:** add sources via MCP `add_source` / the prefs page; the prime security feed is dev.bg IT-security. For Bulgarian-local roles automation can't reach (jobs.bg, LinkedIn), use the `extension/` capture (capture endpoints feed the server pool). Note: scoring `preferredLocations` uses Latin "Sofia" but dev.bg returns Cyrillic "София" — location boost may not match (minor). A leftover ~77 Vercel postings from a plumbing test sit in the pool (no purge tool yet).
